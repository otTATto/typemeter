# 保存データの移行

## 概要

このドキュメントでは、アプリ識別子の変更に伴う保存データの移行と、移行後に旧データを削除する方法を説明します。既存ユーザーが新しいバージョンを初めて起動するときや、旧データの削除を検討するときに読むことを想定しています。具体的には、以下の内容を扱います。

- 起動時に表示される移行確認と、移行先のデータが優先される条件
- 起動後のデータ比較と、旧データを削除できる条件
- 移行や比較でエラーが発生した場合の対応

ただし、以下のような内容は扱っていません。

- 手動でのファイルコピーやスクリプト実行（移行はアプリ内の機能で行います）
- 保存先の OS ごとのパス（詳しくは、[設定ドキュメント](./settings.md#保存先と形式)を参照してください）

旧保存先は `com.taish.typemeter`、新保存先は `bio.tato.typemeter` です。

| バージョン         | アプリフォルダー名    |
| ------------------ | --------------------- |
| v0.1.0-beta.3 まで | `com.taish.typemeter` |
| v0.1.0-beta.4 から | `bio.tato.typemeter`  |

新しい保存先への移行は、アプリに組み込まれた機能で行います。

## 起動時の移行

新保存先にデータがなく、旧保存先に設定とデータベースがそろっている場合、初回起動時にコピーの確認が表示されます。「Copy Data」を選ぶと、`settings.json` と `keystroke.db` が新保存先へコピーされます。「Quit」を選ぶと、データを変更せずアプリを終了します。

新保存先に設定またはデータベースがすでにある場合は、新保存先を優先してコピーを行いません。旧保存先にどちらのファイルもない場合は、移行確認を表示せず通常どおり起動します。旧保存先に片方だけがある場合は不完全なデータとしてエラーを表示し、アプリを終了します。

移行中にエラーが発生した場合は、エラーを表示してアプリを終了します。コピーが完了した後も旧データは削除されず、バックアップとして残ります。つまり、起動時の操作は新保存先へのコピーだけで、旧データの削除は後から選択できます。

## 起動後の確認と旧データの削除

旧データが残っている場合は、起動後に旧・新の保存先とデータの比較結果が表示されます。旧データベースの全レコードと旧設定の全キーが新しいファイルに含まれている場合に限り、「Delete Old Data」ボタンが表示されます。

「Keep Old Data」で閉じた場合、旧データが残っている限り次回起動時にも確認が表示されます。比較に失敗した場合は削除ボタンが表示されず、旧データはそのまま残ります。

「Delete Old Data」を選ぶと、旧保存先の `keystroke.db` と `settings.json` が削除されます。macOS では `.DS_Store` も削除され、フォルダーは空になった場合に限り削除されます。ほかのファイルが残っていればフォルダーは残ります。削除前に表示される比較結果を確認し、旧データを残す場合は「Keep Old Data」を選んでください。

## トラブル時

移行や比較でエラーが表示された場合は、旧・新の保存先を手動で削除・変更せず、そのまま保持してください。移行エラーの場合、旧データは変更されずにアプリが終了します。

エラーの内容と表示された保存先を添えて [GitHub Issues](https://github.com/otTATto/typemeter/issues) に報告してください。原因を確認できるまでは、両方の保存先を残してください。
